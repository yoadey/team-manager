# GHSA-52f5-9888-hmc6 / GHSA-ph9p-34f9-6g65: `tmp` <=0.2.5, reached only via
# @lhci/cli (a devDependency, Lighthouse CI) -> inquirer -> external-editor.
# @lhci/cli never ships to users or production; it runs exclusively inside
# the frontend-lighthouse CI job against a locally built preview server.
# Both advisories require an attacker who can already choose the `dir`/
# prefix/postfix arguments passed to `tmp` -- this codebase never calls
# `tmp` directly, and @lhci/cli's own use of it is not attacker-influenced
# in this repo's CI usage (no untrusted input reaches its arguments).
# `npm audit fix --force` resolves this by downgrading @lhci/cli to 0.1.0
# (a breaking major-version change to an unrelated tool); not applied here
# to avoid destabilizing the Lighthouse CI job on an unrelated fix. Revisit
# when @lhci/cli ships a fixed inquirer/tmp chain on its current major.
GHSA-52f5-9888-hmc6
GHSA-ph9p-34f9-6g65

# GHSA-jmr9-qjv8-65gv: `extract-zip` <=2.0.1 has an unvalidated symlink
# path-traversal when extracting a ZIP whose entries include a symlink
# pointing outside the target directory. Reached only via the same
# @lhci/cli (Lighthouse CI, devDependency) chain as the `tmp` advisories
# above: @lhci/cli -> lighthouse -> puppeteer-core -> @puppeteer/browsers
# -> extract-zip. @puppeteer/browsers uses extract-zip exclusively to
# unpack the Chrome-for-Testing archive it downloads from Google's own
# CDN during the frontend-lighthouse CI job -- the ZIP being extracted is
# never attacker-influenced (it's not a user upload or any other untrusted
# input this repo processes), so the symlink-traversal precondition is not
# reachable here. `npm audit fix --force` resolves this the same way as
# the `tmp` advisories -- downgrading @lhci/cli to 0.1.0 (a breaking
# major-version change) -- not applied here for the same reason. Revisit
# when @lhci/cli ships a fixed puppeteer-core/extract-zip chain on its
# current major.
GHSA-jmr9-qjv8-65gv
